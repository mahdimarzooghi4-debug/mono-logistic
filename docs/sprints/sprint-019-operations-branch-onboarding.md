# Sprint 019 — Mono Operations Branch Onboarding

- Status: In progress
- Phase: A — Platform Foundation
- Epic: E1 — Customer, Contract & Configuration / E20 — Security
- Branch: `sprint-019-operations-branch-onboarding`
- Base: `sprint-018-operations-customer-onboarding`

## Sprint goal

Allow Mono administrators to register a branch for an already-active customer using the shared branch model and an auditable, tenant-scoped write.

## Scope

- Add an administrator-only branch registration route scoped by explicit customer ID.
- Require the customer to be ACTIVE before accepting a branch.
- Generate branch IDs in Mono and apply the existing domain coordinate-pair/range validation.
- Preserve optional operating-hours JSON objects without inventing a schedule schema.
- Persist branch creation and an append-only audit entry in one transaction.
- Add PostgreSQL-backed HTTP integration coverage and operations documentation.

## Acceptance criteria

1. Missing/invalid tokens receive 401 and authenticated non-administrators receive 403.
2. Branch IDs are generated by Mono; request data cannot choose a customer ID.
3. The route rejects unknown customers with 404 and non-active customers with 409.
4. Coordinates are optional but must be supplied as a valid pair.
5. Branch creation and its actor/reason audit entry are committed atomically.
6. No Hana-specific branch data is seeded.
7. CI build, tests, and container image build pass.

## Out of scope

Branch editing/deactivation, zone creation/assignment, operating-hours policy schema, Hana seed data, operations UI, Stage, and deployment.
