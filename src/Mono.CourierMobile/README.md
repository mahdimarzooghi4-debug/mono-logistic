# Mono Courier Mobile

مشتری وب موبایل پیک برای دیدن پیشنهاد، مشاهدهٔ مبدأ و مقصد روی نقشه، قبول یا رد مأموریت و ثبت دستی مراحل تحویل. رابط فعلی، ورود آزمایشی با توکن دستی دارد؛ توکن فقط در حافظهٔ صفحه نگهداری می‌شود. با پاسخ 401 توکن پاک می‌شود و پیک باید دوباره متصل شود.

## اجرا و بررسی

```sh
npm ci
npm test
npm run build
npm run dev
```

در توسعه، سرور روی همهٔ رابط‌های شبکه گوش می‌دهد و مسیرهای `/courier` را به API همان رایانه در `http://localhost:5000` پراکسی می‌کند. رایانه و گوشی را به یک شبکهٔ محلی مطمئن وصل کنید و از گوشی آدرس LAN رایانه به‌همراه پورتی را که Vite در ترمینال اعلام می‌کند باز کنید. این روش برای تست رابط و جریان‌های آزمایشی است؛ توکن واقعی را روی HTTP شبکهٔ محلی وارد نکنید.

## نصب و حالت آفلاین

- نسخهٔ Production با manifest و service worker نصب‌پذیر است؛ پوسته و فایل‌های ثابت رابط cache می‌شوند.
- مسیرهای API زیر `/courier/` هرگز توسط service worker cache نمی‌شوند. ورود، پیشنهادها، نقشهٔ زنده و ثبت مراحل مأموریت همچنان به اینترنت نیاز دارند.
- روی Stage/Production باید اپ از HTTPS ارائه شود تا مرورگر نصب PWA و service worker را فعال کند. تست LAN با HTTP فقط اجرای رابط را بررسی می‌کند و نصب‌پذیری را تأیید نمی‌کند.
- در Android از منوی Chrome گزینهٔ نصب اپ را بزنید؛ در iPhone از Safari گزینهٔ Add to Home Screen را انتخاب کنید.

## پیکربندی نقشه

- `VITE_MAP_STYLE_URL` باید به Style JSON سرویس کاشی خودمیزبان Mono اشاره کند.
- برنامه از MapLibre GL برای نمایش استفاده می‌کند و fallback به tile server عمومی ندارد.
- دادهٔ نمایشی یا مختصات ساختگی نمایش داده نمی‌شود. نشانگرها فقط از پاسخ احرازشدهٔ `GET /courier/v1/mission-offers/{offerId}/route-context` می‌آیند و هر دو مختصات باید معتبر و وضعیت `COMPLETE` باشد.
- وقتی مختصات آماده نیست یا نقشه تنظیم نشده، پیام وضعیت نشان داده می‌شود و نشانگر/مسیر ساخته نمی‌شود.
- انتساب © OpenStreetMap contributors نمایش داده می‌شود. API فعلی مسیر خطی یا ETA برنمی‌گرداند؛ برنامه نیز آن‌ها را حدس نمی‌زند.

## API مورد استفاده

- `GET /courier/v1/session` برای اعتبارسنجی نشست
- `GET /courier/v1/mission-offers` برای پیشنهادها
- `GET /courier/v1/mission-offers/{offerId}/route-context` برای مختصات محدود مبدأ/مقصد
- `POST /courier/v1/mission-offers/{offerId}/accept` و `/decline` با `Idempotency-Key`
- `GET /courier/v1/missions/active` برای بازیابی مأموریت فعال
- `POST /courier/v1/missions/{missionId}/events` برای ثبت دستی مراحل مأموریت با `Idempotency-Key`
- `POST /courier/v1/location` برای ثبت آخرین موقعیت پیک با رضایت صریح
- `DELETE /courier/v1/location` برای پاک‌کردن آخرین نقطه هنگام توقف اشتراک یا پایان مأموریت

## پیش‌نیازهای بیرونی برای محصول

- اتصال OIDC واقعی پیک و توکن کوتاه‌عمر؛ endpoint ورود در این نسخه وجود ندارد.
- سرویس کاشی و Style JSON خودمیزبان روی محیط Stage/Production.
- دامنه و HTTPS محیط Stage/Production برای نصب PWA و استفادهٔ عملی.

## رفتار نشست و مأموریت

- توکن آزمایشی در حافظهٔ صفحه می‌ماند، ذخیرهٔ پایدار نمی‌شود و پس از بارگذاری مجدد باید دوباره وارد شود.
- در پاسخ HTTP 401، توکن پاک و ورودی اتصال دوباره نمایش داده می‌شود؛ 401های متوالی در پس‌زمینه ایجاد نمی‌شوند.
- بعد از پذیرش، مأموریت از `GET /courier/v1/missions/active` بازیابی می‌شود و مراحل چرخهٔ موجود با تأیید دستی پیک ثبت می‌شوند؛ وضعیت از روی GPS حدس زده نمی‌شود.
- پیشنهادها هر ۱۵ ثانیه در حالت نمایان و بدون مأموریت فعال تازه می‌شوند، هنگام بازگشت اپ فوراً به‌روز می‌شوند و در پس‌زمینه polling ندارند.
- مسیریابی با `geo:` به اپ نقشهٔ نصب‌شده واگذار می‌شود.
- اشتراک GPS فقط پس از اقدام پیک، در مأموریت فعال و وقتی صفحه نمایان است کار می‌کند؛ هر ۱۵ ثانیه حداکثر یک به‌روزرسانی فرستاده می‌شود. رفتن به پس‌زمینه ارسال را متوقف می‌کند اما آخرین نقطه را نگه می‌دارد تا بازگشت از مسیریاب جای پیک خالی نشود.
- API موقعیت فقط آخرین نقطه را نگه می‌دارد و تاریخچهٔ مسیر نمی‌سازد. با توقف صریح اشتراک، پایان مأموریت یا خروج دستی، پاک‌سازی سمت سرور درخواست می‌شود؛ در قطع اتصال، پاک‌شدن تضمین نمی‌شود. مصرف‌کنندهٔ آینده باید موقعیت منقضی را بر اساس `observed_at` نمایش ندهد.
